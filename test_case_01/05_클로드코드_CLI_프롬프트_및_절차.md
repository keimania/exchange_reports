## 📋 프로젝트 개요

한국거래소(KRX) 유가증권시장 업무규정 시행세칙을 기반으로 매칭엔진의 빈틈 없는 
테스트케이스를 생성합니다. 단일 호가 조합(9,680건) + 복합 시나리오(10개, 83스텝) + 
에지케이스(25건)를 포함하며, 규정 변경 시 자동 업데이트할 수 있는 구조입니다.

## 🔧 실행 환경 준비

```bash
# 1. 프로젝트 디렉토리 생성
mkdir -p ~/krx-matching-engine-tests/{src,data,output,tests}
cd ~/krx-matching-engine-tests

# 2. 규정 파일 배치
cp "유가증권시장 업무규정 시행세칙_전문_20260209.txt" ./data/

# 3. 첨부된 CSV 파일 배치
cp 01_단일호가_테스트케이스_전체.csv ./data/
cp 02_복합시나리오_목록.csv ./data/
cp 03_복합시나리오_상세스텝.csv ./data/
cp 04_에지케이스_테스트.csv ./data/
```

### [Phase 3] 복합 시나리오 상세 구현

```
claude --print "
src/complex_scenarios.py를 만들어라.

다음 10개 복합 시나리오를 각각 독립적인 테스트 함수로 구현하라.
각 함수는 매칭엔진 API를 호출하는 형태로 작성하되,
실제 엔진이 없는 경우 Mock 객체를 사용하라.

=== 시나리오 목록 ===

CS-001: 시가단일가→시가VI→상한가신규→가격정정→단일가체결→잔량접속전환
- 시가 단일가에서 상한가 매수 주문 후 시가 결정 시 VI 발동
- VI 단일가 중 가격 정정(상한가→기준가+3%)
- VI 해제 후 단일가 체결, 잔량 접속매매 이관
- 검증: VI발동조건, 정정접수, 가격-시간우선원칙, 체결가산출, 잔량이관

CS-002: 접속매매→급등→장중VI→상한가배분→FOK거절
- 대량 시장가 매수로 동적VI 발동
- 상한가 단일가에서 비례배분 (수량정정 포함)
- VI 해제 후 FOK 주문 전량 거부
- 검증: 동적VI기준, 비례배분로직, 수량정정시간순위, FOK처리, 단수주처리

CS-003: 조건부지정가잔량→종가단일가전환→종가VI→정정→취소→체결
- 조건부지정가 미체결 잔량의 종가단일가 시장가 전환
- 종가VI 발동 및 종료시간 연장(1분+랜덤)
- VI 단일가 중 부분취소 처리
- 검증: 조건부→시장가전환, 종가VI, 부분취소, 종가산출

CS-004: 하한가매도쏠림→장중VI→하한가배분→IOC부분체결
- 하한가 매도 쏠림으로 VI 발동
- 하한가 단일가에서 매도 비례배분
- IOC 부분체결 후 잔량 즉시 취소
- 검증: 하한가배분, 시장가단일가우선순위, IOC처리

CS-005: 단기과열종목→1차VI→체결→2차VI→정정→취소→체결→IOC
- 단기과열종목에서 연속 VI 발동 (1차→즉시→2차)
- 각 VI 구간에서 정정/취소 처리
- 검증: 연속VI기준가갱신, 시간우선순위, 단기과열제한

CS-006: 최우선지정가→부분체결→가격정정→최유리매도→VI→종가전환
- 다양한 호가유형 혼합 처리
- 접속매매→종가단일가 전환 시 잔량이관
- 장 종료 전 VI 발동 시 시간연장
- 검증: 호가유형별자동가격결정, 잔량이관, 시간연장

CS-007: 시가단일가 동시호가 배분 + 가격정정 순위변동
- 동일가격 복수 계좌의 시간우선순위
- 가격정정에 의한 우선순위 변동
- 시장가 > 지정가 가격우선
- 검증: 최대체결수량원칙, 배분로직, 정정시순위재설정

CS-008: 관리종목 30분 단일가 전용매매
- 시장가/조건부/최유리/최우선 거부
- 지정가만 허용, 30분 주기 단일가
- 대량매매 거부
- 검증: 종목상태별매매제한

CS-009: 접속매매 정정→부분체결→잔량취소→FOK거부
- 기본적 체결-정정-취소 흐름
- 수량 하향정정 시 시간우선 유지
- FOK 전량 미충족 거부
- 검증: 잔량관리, 정정규칙, FOK처리

CS-010: 풀데이 종합 시나리오 (시가→접속→VI→종가→종가VI)
- 하루 전체 세션 관통
- 조건부지정가의 종가전환
- 장중VI + 종가VI 각각 처리
- 검증: 전세션잔량추적, 세션전환, 미체결소멸

각 시나리오에 대해:
1. setUp(): 초기 호가잔량 설정
2. 각 스텝별 execute_step_N() 함수
3. 각 스텝 후 assert 검증 (체결가, 잔량, 상태)
4. tearDown(): 최종 상태 검증
"
```

### [Phase 4] 추가 시나리오 자동 생성 (규정 기반 확장)

```
claude --print "
src/scenario_expander.py를 만들어라.

기존 10개 복합 시나리오를 기반으로, 다음 규칙에 따라 변형 시나리오를 
자동 생성하는 스크립트를 만들어라:

### 변형 규칙:
1. 매도↔매수 역전: 모든 시나리오에서 매도/매수를 반전한 미러 시나리오
2. 가격 경계값: 상한가/하한가/기준가 경계에서 ±1틱 변형
3. 수량 경계값: 1주/최대주문수량 경계 변형
4. 시간 경계값: 세션 전환 시점(08:59:59/09:00:00, 15:19:59/15:20:00) 변형
5. VI 경계값: VI 발동 기준 정확 충족/미달 변형
6. 종목상태 교차: 동일 시나리오를 관리종목/단기과열종목/정리매매종목에 적용

### 생성 규칙:
- 변형 시 규정 위반이 되는 조합은 '거부 예상' 테스트로 분류
- 각 변형에 고유 ID 부여 (CS-001-V01, CS-001-V02, ...)
- output/expanded_scenarios.csv로 저장
- 예상 총 생성량: 기존 10개 × 변형 6종 = 60개 이상

### 추가 생성할 시나리오 유형:
1. 동일 종목 복수 계좌 동시 주문 (배분 검증)
2. 복수 종목 동시 VI 발동 (시스템 부하 테스트)  
3. 대량매매(장중대량/시간외대량) + 정규 주문 혼합
4. 바스켓매매 + 개별 주문 혼합
5. 프로그램매매 사이드카 발동 시 처리
"
```

### [Phase 5] 테스트 실행 프레임워크

```
claude --print "

### conftest.py:
- pytest fixture로 매칭엔진 Mock 객체 제공
- 매칭엔진 인터페이스 정의:
  - submit_order(order) → OrderResult

  - get_order_book() → OrderBook
  - trigger_single_price_auction() → AuctionResult

  - end_vi() → AuctionResult

- data/ CSV 파일들을 parameterize하여 테스트 자동 실행

- 복합 시나리오 10건 → 각각 독립 테스트 클래스

### 실행 명령:
```bash

pytest tests/ -v --tb=short

# 단일 호가만
pytest tests/test_matching_engine.py -k 'single' -v

# 복합 시나리오만
pytest tests/test_matching_engine.py -k 'complex' -v

# 에지케이스만
pytest tests/test_matching_engine.py -k 'edge' -v

# 특정 시나리오만
pytest tests/test_matching_engine.py -k 'CS_001' -v
```
"
```

## ⚠️ 주의사항

1. 규정 업데이트 시 Phase 1의 JSON만 수정하면 후속 Phase가 자동 반영되도록 설계
2. 실제 매칭엔진 API가 확정되면 conftest.py의 Mock을 실제 클라이언트로 교체
3. 복합 시나리오의 수치(가격/수량)는 예시이며, 실제 종목의 호가가격단위에 맞게 조정 필요
4. VI 발동 기준값(정적VI: ±10%, 동적VI: ±3~6%)은 거래소 공시 기준으로 설정
