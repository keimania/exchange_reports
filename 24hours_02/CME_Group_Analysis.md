## 1. 기관 개요 및 시장 내 위상

CME Group은 시카고상업거래소(CME), 시카고상품거래소(CBOT), 뉴욕상업거래소(NYMEX), 뉴욕상품거래소(COMEX)를 통합 운영하는 세계 최대의 파생상품 거래소이다. 일일 평균 **2,000만 건 이상의 청산 트랜잭션**을 처리하며, 금리·주가지수·외환·에너지·농산물·금속 등 전 자산군에 걸쳐 선물 및 옵션 상품을 제공한다.

CME Group의 핵심 경쟁력은 **사실상 24시간 연속 운영**에 있다. 주식 현물시장(NYSE, NASDAQ)이 일일 60분 이상의 시스템 점검 시간을 필요로 하는 것과 달리, CME Globex는 **단 1분의 유지보수 윈도우**만으로 일요일 저녁부터 금요일 오후까지 끊김 없는 거래 환경을 제공한다. 이는 글로벌 파생상품 시장에서 연속성(continuity)과 유동성(liquidity)의 표준을 정의하는 수준이다.

| 항목 | CME Group | 참고 (NYSE/NASDAQ) |
|------|-----------|---------------------|
| 일일 청산 건수 | 2,000만+ 건 | 약 500만 건 |
| 자산군 | 6개 대분류 (금리, 지수, FX, 에너지, 농산물, 금속) | 주식·ETF 중심 |
| 일일 유지보수 시간 | **1분** (16:00-16:01 CT) | 약 60분 |
| 주간 운영 시간 | 일요일 17:00 CT ~ 금요일 16:00 CT | 월~금 정규장 6.5시간 |
| 매칭 엔진 세그먼트 | 17개 수평 파티션 | 단일 또는 수 개 |

## 2. 현행 거래 제도

### 2.1 거래 시간 및 세션 구조

CME Globex의 거래 시간은 **일요일 17:00 CT(중부표준시)부터 금요일 16:00 CT**까지로, 주중 거의 연속적으로 운영된다. 이를 한국 시간(KST, UTC+9)으로 환산하면 월요일 08:00 KST부터 토요일 07:00 KST에 해당한다.

#### 일일 세션 구조

| 시간 (CT) | 이벤트 | 설명 |
|-----------|--------|------|
| 16:00 | **장 마감** | 모든 매칭 엔진 정지, 일일 정산가 확정 |
| 16:00 ~ 16:01 | **1분 유지보수** | 시스템 점검, 내부 인덱스 리셋 |
| 16:01 ~ | **Pre-Open / 장 재개** | 주문 접수 재개, 호가 축적 후 매칭 시작 |
| 16:30 | **포지션 리셋** | 일일 포지션 제로 리셋 (정산 기준) |

#### 주간 확장 유지보수

| 시간 (CT) | 요일 | 설명 |
|-----------|------|------|
| 화요일 02:00 ~ 03:45 | 매주 화요일 | 확장 유지보수 (1시간 45분) + 15분 Pre-Open |
| 토요일 02:00 ~ 03:45 | 매주 토요일 | 확장 유지보수 + **FIX 시퀀스 번호 하드 리셋** |

토요일의 FIX 시퀀스 번호 리셋은 주간 단위로 세션 상태를 초기화하는 핵심 절차로, iLink 3 프로토콜의 UUID 기반 세션 관리와 밀접하게 연관된다. 이 리셋을 통해 시퀀스 번호 오버플로우 가능성을 원천 차단하고, 주간 시작 시 깨끗한 세션 상태를 보장한다.

### 2.2 1분 유지보수 윈도우의 혁신

CME의 **1분 유지보수 윈도우**는 거래소 운영 역사상 가장 공격적인 연속 운영 설계이다. 이 극단적으로 짧은 중단이 가능한 이유는 다음과 같다.

1. **Dual Zone 아키텍처**: 두 개의 격리된 프로덕션 존이 교대 운영되므로, 비활성 존에서 사전 패치·검증 완료 후 1분 내 전환이 가능하다.
2. **FIXP 세션 지속성**: TCP 연결이 끊어져도 UUID 기반 세션이 보존되어, 재접속 시 주문 큐 우선순위가 유지된다.
3. **GTC/GTD 주문 보존**: Good-Till-Cancel / Good-Till-Date 주문은 1분 중단 구간을 관통하며 **타임스탬프 우선순위를 그대로 유지**한다.
4. **자동화된 리스크 제어 토글**: 유지보수 진입·퇴출 시 리스크 한도가 자동으로 비활성화·재활성화된다.

| 비교 항목 | CME Globex | 미국 주식거래소 | KRX (현행) |
|-----------|-----------|---------------|-----------|
| 일일 유지보수 | 1분 | ~60분 | 야간 전체 (약 15시간) |
| 주문 우선순위 보존 | O (타임스탬프 유지) | 해당 없음 | 해당 없음 |
| 세션 재접속 자동화 | UUID 기반 자동 복구 | 부분적 | 재로그인 필요 |

### 2.3 주문 유형 및 BTIC/TACO 메커니즘

CME는 표준 주문 유형(시장가, 지정가, 역지정가 등) 외에 선물-현물 간 교량 역할을 하는 고유한 메커니즘을 제공한다.

#### BTIC (Basis Trade at Index Close)

BTIC는 **주가지수 선물을 해당 주가지수의 종가(closing price) 기준**으로 거래하는 메커니즘이다. 선물 세션 중에 주문을 체결하되, 최종 가격은 현물 지수의 종가가 확정된 후 결정된다.

- **용도**: 기관투자자가 현물 포트폴리오의 종가 벤치마크에 맞추어 선물 헤지를 실행
- **결제**: 선물 체결가 = 현물 지수 종가 + 체결 시 합의한 베이시스(basis)

#### TACO (Trade at Cash Open)

TACO는 BTIC의 반대 개념으로, **주가지수의 개장가(opening price) 기준**으로 선물을 거래한다.

- **용도**: 아시아·유럽 시간대 투자자가 미국 주식시장 개장 전에 개장가 기준 선물 포지션을 구축
- **의의**: 24시간 선물 세션과 이산적(discrete) 현물 시장 가격 이벤트를 연결하는 핵심 도구

| 메커니즘 | 기준 가격 | 거래 시점 | 가격 확정 시점 |
|----------|----------|----------|--------------|
| BTIC | 현물 지수 종가 | 선물 세션 중 수시 | 현물 장 마감 후 |
| TACO | 현물 지수 개장가 | 선물 세션 중 수시 | 현물 장 개장 후 |
| 일반 선물 | 선물 자체 호가 | 선물 세션 중 수시 | 즉시 |

이 메커니즘들은 KRX가 24시간 파생상품 거래를 도입할 경우, KOSPI 200 선물과 KOSPI 200 현물지수 간의 연계를 설계하는 데 직접적인 참고 모델이 된다.

## 3. 핵심 시스템 인프라

### 3.1 CME Globex 매칭 엔진 (17 Market Segments)

CME Globex 매칭 엔진은 **17개의 독립적인 Market Segment**로 수평 분할(horizontal partitioning)되어 있다. 각 세그먼트는 자산군별로 구분되며, 독립적인 매칭 로직과 호가창(order book)을 보유한다.

#### 수평 파티셔닝의 장점

| 설계 원칙 | 효과 |
|-----------|------|
| **장애 격리 (Fault Isolation)** | 한 세그먼트의 장애가 타 세그먼트에 전파되지 않음 |
| **독립 배포** | 세그먼트별 소프트웨어 업데이트 가능 |
| **지연시간 최적화** | 세그먼트별 전용 하드웨어 자원 할당 |
| **용량 확장** | 세그먼트 추가로 수평 확장 가능 |

#### 게이트웨이 모델

CME는 두 가지 게이트웨이 모델을 제공하며, 참여자의 요구사항에 따라 선택할 수 있다.

| 게이트웨이 | 약칭 | 연결 방식 | 특성 | 대상 사용자 |
|-----------|------|----------|------|-----------|
| **Convenience Gateway** | CGW | 단일 TCP 연결, 중앙 집중형 | 복수 세그먼트 접근 용이, 구현 단순 | 일반 참여자, 브로커 |
| **Market Segment Gateway** | MSGW | 세그먼트별 직접 연결, MTU 1,420 byte | 초저지연(ultra-low latency), 직접 매칭 엔진 접근 | HFT, 마켓 메이커 |

MSGW의 **1,420바이트 MTU 제한**은 의도적 설계로, 단일 이더넷 프레임 내에서 패킷 분할(fragmentation) 없이 주문 메시지를 전송하여 지연시간 변동성(jitter)을 최소화한다. 이는 FPGA 가속 게이트웨이와 결합하여 마이크로초(μs) 단위의 결정론적 처리를 가능하게 한다.

### 3.2 iLink 3 / MDP 3.0 프로토콜

#### iLink 3 (주문 전송 프로토콜)

iLink 3은 CME의 차세대 주문 진입 프로토콜로, 두 가지 핵심 계층으로 구성된다.

| 계층 | 기술 | 특성 |
|------|------|------|
| **세션 계층** | FIXP (FIX Performance Session Layer) | UUID 기반 세션 관리, TCP 단절 후 복구 지원 |
| **인코딩** | SBE (Simple Binary Encoding) | 고정 길이 필드, 리틀엔디안, 직접 메모리 매핑 |

SBE 인코딩의 핵심 설계 철학은 **제로 파싱(zero-parsing)**이다. 고정 길이 필드와 리틀엔디안 바이트 순서를 사용함으로써, 수신 측에서 별도의 역직렬화(deserialization) 과정 없이 메모리에 직접 매핑하여 필드 값을 읽을 수 있다. 이는 FIX 태그-값 텍스트 프로토콜 대비 수십 마이크로초의 처리 시간을 절감한다.

**FIXP 세션 지속성**은 24시간 연속 운영의 기반 기술이다:
- 각 세션에 UUID가 부여되며, TCP 연결 단절 시에도 세션 상태가 서버에 보존된다
- 재접속 시 UUID와 마지막 수신 시퀀스 번호를 제시하면 미전송 메시지부터 재전송(retransmission)이 이루어진다
- **주문 큐 내 우선순위가 보존**되므로, 1분 유지보수 윈도우 전후로 참여자의 포지션이 불이익을 받지 않는다

#### MDP 3.0 (시장 데이터 프로토콜)

| 항목 | 사양 |
|------|------|
| 전송 방식 | **이중 피드 UDP 멀티캐스트** (Feed A / Feed B) |
| 인코딩 | SBE (주문 프로토콜과 동일) |
| 핵심 태그 | **MatchEventIndicator (tag 5799)** — 매칭 이벤트 경계 표시 |
| 피드 구조 | Incremental + Snapshot (주기적 전체 호가창 복구용) |

**MatchEventIndicator (tag 5799)**는 MDP 3.0의 고유 설계로, 단일 매칭 이벤트(예: 하나의 공격적 주문이 복수의 대기 주문과 체결되는 과정)가 여러 UDP 패킷에 걸쳐 전송될 때 이벤트의 시작과 끝을 표시한다. 이를 통해 수신 측은 부분적 상태 업데이트를 방지하고, 원자적(atomic) 호가창 갱신을 수행할 수 있다.

### 3.3 Zero-Downtime 아키텍처 (Dual Zone / Blue-Green)

CME의 제로 다운타임 아키텍처는 세 가지 상호보완적 메커니즘으로 구성된다.

#### (1) Dual Zone 구조

```
┌─────────────────────────────────────────────┐
│              CME Aurora 데이터센터              │
│                                             │
│  ┌──────────────┐    ┌──────────────┐       │
│  │   Zone A     │    │   Zone B     │       │
│  │  (활성)       │    │  (대기/패치)   │       │
│  │              │    │              │       │
│  │ 매칭 엔진     │    │ 매칭 엔진     │       │
│  │ 게이트웨이    │◄──►│ 게이트웨이    │       │
│  │ 리스크 엔진   │    │ 리스크 엔진   │       │
│  └──────────────┘    └──────────────┘       │
│          │                    │              │
│          └────────┬───────────┘              │
│                   │                         │
│           ┌───────┴───────┐                 │
│           │ 로드 밸런서    │                 │
│           └───────────────┘                 │
└─────────────────────────────────────────────┘
```

두 개의 격리된 프로덕션 존이 존재하며, 한 존이 거래를 처리하는 동안 다른 존에서 패치·업그레이드·검증이 수행된다. 전환(cutover)은 로드 밸런서 레벨에서 이루어지며, 1분 유지보수 윈도우 내에 완료된다.

#### (2) Blue-Green Deployments

| 단계 | 활동 | 소요 시간 |
|------|------|----------|
| 1. 준비 | Blue 환경에서 거래 진행 중, Green 환경에 새 버전 배포 | 수 시간 (사전) |
| 2. 검증 | Green 환경에서 합성 트래픽으로 회귀 테스트 수행 | 수 시간 (사전) |
| 3. 전환 | 로드 밸런서가 트래픽을 Green으로 리디렉션 | < 1분 |
| 4. 롤백 대기 | Blue 환경을 일정 시간 유지하여 즉시 롤백 가능 | 수 시간 (사후) |

#### (3) Dynamic Feature Flags

데이터베이스 스키마 변경 등 위험도 높은 변경사항은 **피처 플래그(feature flag)**로 래핑된다. 이를 통해:
- 새 기능을 코드 배포와 분리하여 활성화/비활성화 가능
- 문제 발생 시 전체 롤백 없이 해당 기능만 비활성화
- A/B 테스트 형태로 일부 Market Segment에만 선제 적용 가능

### 3.4 데이터센터 및 재해복구

#### Aurora 데이터센터

| 항목 | 사양 |
|------|------|
| 위치 | 일리노이주 오로라 |
| 면적 | **428,000 평방피트** (약 39,762㎡) |
| 등급 | **Tier-3** (99.982% 가용성) |
| 코로케이션 | **등거리 케이블링 프로토콜** — 모든 참여자에게 동일 광케이블 길이 보장 |
| 게이트웨이 | **FPGA 가속** 게이트웨이 |

등거리 케이블링 프로토콜은 공정성(fairness)의 물리적 구현이다. 코로케이션 랙의 물리적 위치와 무관하게 모든 참여자의 광케이블 길이를 동일하게 유지함으로써, 물리적 거리에 의한 지연시간 차이를 원천적으로 제거한다.

#### 재해복구 (DR) 체계

CME는 Aurora 데이터센터 외에 뉴욕 데이터센터(NYDC)를 DR 사이트로 운영하며, 4단계 DR 프로세스를 수행한다.

| 단계 | 명칭 | 활동 | 예상 소요 |
|------|------|------|----------|
| 1 | **Pre-Event** | 위험 감지, DR 발동 의사결정, 참여자 통보 | 가변 |
| 2 | **DR (Disaster Recovery)** | NYDC로 전환, 거래 재개 | **45분 스테이징** |
| 3 | **Recovery** | Aurora 복구 작업, 데이터 동기화 | 수 시간~수 일 |
| 4 | **Post-Recovery** | Aurora 복귀, 정상 운영 전환 | 계획적 실행 |

45분 스테이징 시간은 참여자들이 NYDC 연결로 전환하고, 세션을 재수립하며, 호가창을 동기화하는 데 필요한 최소 시간이다.

## 4. 청산·결제 체계

### 4.1 CME Clearing CCP 구조

CME Clearing은 **중앙청산소(CCP, Central Counterparty)**로서 모든 거래의 매수자에 대해 매도자가 되고, 매도자에 대해 매수자가 되어 결제 이행을 보증한다. 일일 **2,000만 건 이상의 트랜잭션**을 처리한다.

#### 주요 마감 시한 (CT 기준)

| 시한 | 대상 | 설명 |
|------|------|------|
| **16:00 CT** | 전 상품 | 장 마감, 일일 정산가 확정 |
| **16:30 CT** | 포지션 | 일일 포지션 제로 리셋 |
| **18:00 CT** | 전자 거래 | **프론트엔드 청산 마감** (전자 거래분) |
| **18:15 CT** | 옵션 | **행사/포기(Exercise/Abandon) 마감** |
| **19:00 CT** | 비전자 거래 | **프론트엔드 청산 마감** (비전자 거래분) |
| **20:00 CT** | 청산보증 | **Clearing Guarantee Module 종료** |

이 시한 구조는 24시간 거래 환경에서 청산 사이클의 명확한 경계를 설정한다. 거래는 거의 연속적으로 이루어지지만, 청산·결제는 일일 단위로 정리되며, 16:00~20:00 CT의 4시간이 사실상의 "청산 처리 윈도우"로 기능한다.

### 4.2 BAMS 증거금 관리

**BAMS (Banking and Margin System)**는 CME의 증거금 관리 및 은행간 자금 이동 시스템이다.

| 항목 | 사양 |
|------|------|
| 프로토콜 | **FIXML** (FIX Markup Language) |
| 전송 방식 | **SFTP** (Secure File Transfer Protocol) |
| 증거금 산출 | SPAN (Standard Portfolio Analysis of Risk) + CORE |
| 일중 증거금 콜 | 지원 (intraday margin call) |
| 통화 | 다중 통화 지원 (USD, EUR, GBP, JPY 등) |

BAMS는 FIXML/SFTP 기반으로 청산회원과 CME Clearing 간에 증거금 보고서, 마진콜 통지, 자금 이동 지시를 교환한다. 이 배치(batch) 기반 처리 방식은 24시간 거래 환경에서도 청산 사이클의 일일 단위 운영을 지원하는 핵심 인프라이다.

## 5. 리스크 관리

### 5.1 Globex Credit Controls (GC2)

GC2는 CME Globex의 **실시간 사전 거래 리스크 관리** 시스템으로, 주문이 매칭 엔진에 도달하기 전에 리스크 한도를 점검한다.

| 통제 항목 | 설명 | 특성 |
|----------|------|------|
| **Exposure Limits** | 통화 기반 익스포저 한도 | 순 포지션의 증거금 소요액 기준 |
| **Maximum Quantity** | 단일 주문 최대 수량 제한 | 팻핑거(fat finger) 방지 |
| **Conservative Logic** | 보수적 산출 로직 | 최악의 시나리오 기준 한도 적용 |

#### 자동 주말 한도 토글

| 시점 | 동작 |
|------|------|
| **금요일 16:00 CT** (주말 시작) | 모든 익스포저 한도를 **제로(0)로 자동 전환** |
| **일요일 저녁** (주간 시작 전) | 기존 한도로 **자동 복원** |

이 자동 토글 메커니즘은 주말 동안의 무단 거래 시도를 시스템 레벨에서 원천 차단하며, 인적 오류에 의한 리스크를 제거한다.

### 5.2 Kill Switch 및 Dynamic Price Banding

#### Kill Switch

CME의 Kill Switch는 긴급 상황 시 특정 참여자의 모든 거래 활동을 즉시 중단하는 메커니즘이다.

| 항목 | 사양 |
|------|------|
| 발동 조건 | 청산회원 또는 CME 리스크팀의 수동 발동 / 자동 트리거 |
| 반응 시간 | **1초 이내** 활성화 |
| 동작 | (1) 신규 주문 차단, (2) 기존 미체결 주문 **일괄 취소(mass cancel)** |
| 복구 | 명시적 해제 절차 필요 |

Kill Switch의 1초 이내 반응은 FPGA 가속 게이트웨이와 매칭 엔진의 병렬 처리 능력에 의해 보장된다. 이는 알고리즘 오작동(rogue algorithm)이나 사이버 공격 시 시장 전체에 대한 파급을 최소화하는 최후의 방어선이다.

#### Dynamic Price Banding

| 항목 | 설명 |
|------|------|
| 방식 | **알고리즘 기반** 동적 가격 밴드 산출 |
| 기준 | 직전 체결가, 이론가, 변동성 등 복합 요소 |
| 밴드 초과 시 | 주문 거부 또는 일시적 매칭 중단 |
| 수동 개입 | **GCC(Globex Control Center)**가 밴드를 수동으로 확대 가능 |

Dynamic Price Banding은 급격한 가격 변동 시 자동으로 밴드를 조정하여, 전통적인 고정 가격제한폭(static price limit)의 한계를 극복한다. GCC가 시장 상황을 판단하여 수동으로 밴드를 확대할 수 있는 점은, 순수 자동화와 인적 판단의 균형을 보여준다.

### 5.3 Self-Match Prevention (SMP)

| 항목 | 사양 |
|------|------|
| 의무 여부 | **필수(mandatory)** |
| 식별 태그 | **tag 2362** (SMP ID) |
| 동작 | 동일 참여자(또는 그룹)의 매수·매도 주문이 상호 체결되는 것을 방지 |
| 적용 수준 | 계좌, 참여자 그룹 등 설정 가능 |

SMP는 시장 조작(wash trading) 방지와 규제 준수를 위한 필수 메커니즘이다. iLink 3 프로토콜의 tag 2362에 SMP 식별자를 기재하여 매칭 엔진이 자기거래(self-trade)를 사전에 차단한다. CME에서 이를 **의무화**한 것은, 24시간 거래 환경에서 다수의 알고리즘이 동시 운영될 때 의도치 않은 자기거래 위험이 증가하기 때문이다.

| **DR 체계** | 4단계 DR, 45분 스테이징 | DR 체계 운영 | 전환 프로세스 표준화 수준 |
| **청산 CCP** | CME Clearing (2,000만+/일) | KRX CCP | 처리 용량 차이 |

### 6.2 KRX 24시간 거래 도입 시 핵심 시사점

#### (1) 파생상품 모델의 검증

CME의 사례는 **파생상품 시장이 사실상 24시간 연속 운영 가능함을 실증**한다. 단 1분의 유지보수 윈도우로 주중 연속 운영이 가능하다는 것은, KRX 파생상품 시장(KOSPI 200 선물·옵션 등)이 야간 세션 공백을 대폭 축소할 수 있는 기술적 기반이 존재함을 의미한다.

#### (2) Follow-the-Sun 운영 모델

| 교대 지역 | 커버리지 (CT) | KRX 적용 시 (KST) |
|-----------|-------------|-------------------|
| **아시아/태평양** | 17:00~01:00 | 08:00~16:00 |
| **유럽/중동/아프리카** | 01:00~09:00 | 16:00~00:00 |
| **아메리카** | 09:00~17:00 | 00:00~08:00 |

CME는 세 지역의 운영팀이 교대 근무(overlapping shifts)하는 Follow-the-Sun 모델로 24시간 인적 모니터링을 구현한다. KRX가 24시간 운영으로 전환할 경우, 유사한 글로벌 운영 체계가 필요하며, 최소 서울·런던·시카고(또는 뉴욕)에 운영 거점을 확보해야 한다.

#### (3) 교차증거금(Cross-Margining) API

24시간 파생상품 거래 시 **야간 KOSPI 선물 포지션과 현물 주식 포지션 간 교차증거금** 산출이 핵심 과제가 된다. CME의 BAMS/SPAN 모델을 참고하여:
- 야간 시간대 선물 포지션 변동에 대한 실시간 증거금 재산출 API
- 현물 포지션(장 마감 후 고정)과 선물 포지션(야간 변동) 간의 상관관계 기반 증거금 경감
- 일중 증거금 콜(intraday margin call) 인프라 구축

#### (4) Cancel-on-Disconnect 정책

연장 거래 시간에서는 시스템 장애나 네트워크 단절 시 미체결 주문의 처리가 중요하다. CME의 **Cancel-on-Disconnect** 정책을 참고하여:
- 야간 세션에서 참여자 연결 단절 시 미체결 주문 자동 취소
- 단, GTC/GTD 주문은 예외 처리 (세션 간 유지)
- 취소 대상 주문의 범위와 지연시간 기준 정의

#### (5) 인프라 현대화 로드맵

| 단계 | 목표 | CME 벤치마크 |
|------|------|-------------|
| **1단계** | 야간 세션 공백 축소 (15:45~18:00 제거) | 1분 유지보수 윈도우 |
| **2단계** | 매칭 엔진 수평 분할 | 17 Market Segments |
| **3단계** | Dual Zone 아키텍처 도입 | Zero-Downtime 배포 |
| **4단계** | 프로토콜 현대화 (바이너리 인코딩) | iLink 3 / SBE |
| **5단계** | 등거리 케이블링 코로케이션 | Aurora 등거리 프로토콜 |

### 6.3 BTIC/TACO 모델의 KRX 적용 가능성

CME의 BTIC/TACO 메커니즘은 KRX가 24시간 파생상품 거래를 도입할 때, **KOSPI 200 선물과 현물지수 간 교량 역할**을 하는 유사 상품 설계의 직접적 모델이 된다.

| CME 메커니즘 | KRX 적용 모델 (제안) | 용도 |
|-------------|---------------------|------|
| BTIC | **KOSPI 선물 종가연계거래** | 야간 세션에서 익일 현물 종가 기준 선물 거래 |
| TACO | **KOSPI 선물 개장가연계거래** | 야간 세션에서 익일 현물 개장가 기준 선물 거래 |

이러한 메커니즘을 통해 야간 시간대의 글로벌 투자자들이 한국 현물시장의 핵심 가격 이벤트(개장·마감)에 대한 익스포저를 구축할 수 있으며, 이는 KOSPI 파생상품의 글로벌 유동성 확대에 기여할 것이다.
